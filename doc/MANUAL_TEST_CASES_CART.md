# Manual Test Cases: Shopping Cart

These manual test cases are formatted for Jira import or Jira test case entry. Each case includes a test ID, preconditions, test steps, expected results, and priority.

| Test ID | Preconditions | Test Steps | Expected Results | Priority |
|---|---|---|---|---|
| CART-TC-001 | Application is running. User is not logged in. At least one product exists. | 1. Open the product list page. 2. Click the add-to-cart action for any product. | User is redirected to the login page. Product is not added to an anonymous cart. | High |
| CART-TC-002 | Application is running. User is not logged in. | 1. Navigate directly to `/cart/`. | User is redirected to the login page because cart access requires authentication. | High |
| CART-TC-003 | Application is running. A valid user account exists. User is logged in. No cart exists for the user. At least one product exists. | 1. Open the product list page. 2. Add a product to the cart. 3. Navigate to the cart page. | A cart is created for the logged-in user. The selected product appears in the cart with quantity `1`. | High |
| CART-TC-004 | User is logged in. User has an empty cart. | 1. Navigate to `/cart/`. | Cart page loads successfully. Empty cart message is displayed. Browse Products button/link is displayed. | Medium |
| CART-TC-005 | User is logged in. User has an empty cart. | 1. Navigate to `/cart/`. 2. Click Browse Products. | User is redirected to the product list page. | Medium |
| CART-TC-006 | User is logged in. At least one product exists. | 1. Open the product list page. 2. Add the same product to the cart once. 3. Open the cart page. | Product name, quantity/unit details, and cart item quantity are displayed correctly. | High |
| CART-TC-007 | User is logged in. Product A exists. Product A is not already in the user's cart. | 1. Add Product A to the cart. 2. Add Product A to the cart again. 3. Open the cart page. | Product A appears only once in the cart. Cart item quantity is incremented to `2`. | High |
| CART-TC-008 | User is logged in. Product A and Product B exist. Cart is empty. | 1. Add Product A to the cart. 2. Add Product B to the cart. 3. Open the cart page. | Both Product A and Product B are displayed as separate cart items. Each item has quantity `1`. | High |
| CART-TC-009 | User is logged in. Cart contains Product A with quantity `1`. | 1. Open the cart page. 2. Change Product A quantity to `3`. 3. Submit the update form. | User remains on or is redirected back to the cart page. Product A quantity is updated to `3`. | High |
| CART-TC-010 | User is logged in. Cart contains Product A with quantity greater than `1`. | 1. Open the cart page. 2. Change Product A quantity to `1`. 3. Submit the update form. | Product A quantity is updated to `1`. Product remains in the cart. | Medium |
| CART-TC-011 | User is logged in. Cart contains Product A. | 1. Open the cart page. 2. Change Product A quantity to `0` if the browser allows the value. 3. Submit the update form. | Product A is removed from the cart. If it was the only item, the empty cart message is displayed. | High |
| CART-TC-012 | User is logged in. Cart contains Product A. | 1. Open the cart page. 2. Change Product A quantity to `-1` if the browser allows the value. 3. Submit the update form. | Product A is removed from the cart because non-positive quantity values are treated as removal. | Medium |
| CART-TC-013 | User is logged in. Cart contains Product A. Browser dev tools or request editing is available. | 1. Submit the update cart item request with quantity value `abc`. 2. Return to the cart page. | Product A quantity is not changed. An error message is shown indicating a valid quantity is required. | High |
| CART-TC-014 | User is logged in. Cart contains Product A. | 1. Open the cart page. 2. Click Delete for Product A. | Product A is removed from the cart. User is redirected back to the cart page. | High |
| CART-TC-015 | User is logged in. Cart contains only Product A. | 1. Open the cart page. 2. Click Delete for Product A. | Product A is removed. Cart page displays the empty cart state. | High |
| CART-TC-016 | User is logged in. Cart contains Product A and Product B. | 1. Open the cart page. 2. Click Delete for Product A. | Product A is removed. Product B remains in the cart with its existing quantity. | High |
| CART-TC-017 | Two user accounts exist: User A and User B. Product A exists. User A has Product A in cart. User B is logged in. | 1. As User B, attempt to access User A's update cart item URL directly using User A's cart item ID. | User B cannot update User A's cart item. Application returns not found or an equivalent protected response. User A's cart remains unchanged. | High |
| CART-TC-018 | Two user accounts exist: User A and User B. Product A exists. User A has Product A in cart. User B is logged in. | 1. As User B, attempt to access User A's remove cart item URL directly using User A's cart item ID. | User B cannot remove User A's cart item. Application returns not found or an equivalent protected response. User A's cart remains unchanged. | High |
| CART-TC-019 | Two user accounts exist. User A and User B each have different cart contents. | 1. Log in as User A. 2. Open cart page and note items. 3. Log out. 4. Log in as User B. 5. Open cart page. | User B sees only User B's cart items. User A's cart items are not displayed. | High |
| CART-TC-020 | User is logged in. Cart contains at least one product with an uploaded image. | 1. Open the cart page. | Product image is displayed next to the cart item. Image alt text matches the product name. | Low |
| CART-TC-021 | User is logged in. Cart contains at least one product without an uploaded image. | 1. Open the cart page. | Placeholder image/icon area is displayed for the product. Page layout remains intact. | Low |
| CART-TC-022 | User is logged in. Cart contains Product A. | 1. Open the cart page. 2. Click Continue Shopping. | User is redirected to the product list page. Existing cart contents are preserved. | Medium |
| CART-TC-023 | User is logged in. Cart contains Product A. | 1. Open the cart page. 2. Refresh the browser. | Cart page reloads successfully. Product A remains visible with the same quantity. | Medium |
| CART-TC-024 | User is logged in. Cart contains Product A. | 1. Log out. 2. Log back in with the same account. 3. Open the cart page. | Previously added Product A is still in the user's cart. | Medium |
| CART-TC-025 | User is logged in. Product A exists. | 1. Add Product A to the cart. 2. Observe the page after submission. | User is redirected to the product list page after the add-to-cart action. | Medium |
| CART-TC-026 | User is logged in. Product A exists. Product A is later deleted by an admin or through product delete workflow. | 1. Add Product A to cart. 2. Delete Product A from product management. 3. Open cart page. | Related cart item is removed through cascade behavior. Cart page does not error. | Medium |
| CART-TC-027 | User is logged in. Cart contains Product A. | 1. Open cart page on desktop viewport. 2. Verify item layout, quantity input, update button, delete button, and continue shopping link. | Cart page is readable and controls are usable without overlapping elements. | Low |
| CART-TC-028 | User is logged in. Cart contains Product A. | 1. Open cart page on mobile viewport. 2. Verify item layout, quantity input, update button, delete button, and continue shopping link. | Cart page is responsive. Controls remain visible and usable on mobile. | Low |
| CART-TC-029 | User is logged in. Cart contains Product A. | 1. Open cart page. 2. Use keyboard navigation to reach quantity input, update button, delete link, and continue shopping link. | Main cart controls are reachable and operable by keyboard. | Medium |
| CART-TC-030 | User is logged in. Cart contains Product A. Browser dev tools or request editing is available. | 1. Submit update cart item request without a `quantity` value. | Application uses default quantity behavior or shows validation handling without a server error. Cart page remains accessible. | Medium |
| CART-TC-031 | User is logged in. Cart contains Product A. | 1. Open cart page. 2. Enter a very large quantity such as `999999`. 3. Submit the update form. | Application handles the value without crashing. Quantity is either saved if accepted or validation feedback is shown if rejected. | Medium |
| CART-TC-032 | User is logged in. No cart exists for the user. | 1. Navigate directly to `/cart/`. | A new empty cart is created for the user. Empty cart page displays successfully. | Medium |
| CART-TC-033 | User is logged in. Product A exists. | 1. Navigate directly to `/cart/add/<product_id>/` for Product A. | Product A is added to cart. User is redirected to product list page. | Medium |
| CART-TC-034 | User is logged in. Product ID does not exist. | 1. Navigate directly to `/cart/add/<invalid_product_id>/`. | Application returns an error response or 404. No cart item is created. | Medium |
| CART-TC-035 | User is logged in. Cart contains Product A. | 1. Navigate directly to `/cart/remove/<valid_item_id>/`. | Matching cart item is removed. User is redirected to cart page. | Medium |
| CART-TC-036 | User is logged in. Cart contains Product A. | 1. Open cart page. 2. Update quantity using the visible update button labelled on the page. | Quantity update is submitted successfully. Button label does not prevent the update workflow from working. | Low |
